## 1. 现有分类 / 标签怎么工作

### 1.1 内容位置与 schema

- 文章在 **sayori-articles** 的 `posts/<slug>/<slug>.md`（中文）+ 同目录 `.en.md`（英文配对；发布校验强制）。
- 博客构建时把内容仓检出到 `content/`，由 `src/content.config.ts` 的 `posts` collection 加载。
- 关键 frontmatter 字段（与曝光相关）：
  - `category: string` — **单分类**（侧栏 categories 聚合）
  - `tags: string[]` — **多标签**（侧栏 tags / 文章页）
  - `section: "main" | "deals"` — 分区；`deals` 用于羊毛/权益类（现有 7 篇）
  - `pinned` / `priority` / `draft` / `essay` — 置顶与草稿等
- 公开专题路由源：`sayori-blog/src/data/topics.ts`（目前仅 `webmaster`「个人站长工具箱」）。
- 首页作品介绍（DelayTrace / TimeRewindLinker 等）在 **sayori-articles** 的 `home/*.json`，与博客 posts 分类独立。

英文译文常用对应名（如 `Game Development`），中英 category 字符串目前**未强制统一**。

### 1.3 高频 tags（示意）

叙事、资源整合、教程、独立博客、成长回顾、随笔、复盘、自托管、Docker、独立游戏、隐私、学生资源、中文社区、创作者、游戏开发、Cloudflare、Godot、game-jam …

**结论：** 分类是粗路由；标签是细主题。品牌重定位后，「主线留存 / 降曝光」应是**运营可见性层**（首页/导航/专题/置顶），**不要删文**；可用现有 `category`+`tags`+`section`+`topics.ts` 映射，必要时再加可选 frontmatter（见下）。

## 2. 主线留存 vs 降曝光

### 2.1 判定规则

| 维度 | 主线留存（高可见） | 降曝光（降导航/精选，保留 URL） |
| --- | --- | --- |
| 品牌契合 | Godot / 独立游戏 / 时间·多窗口·叙事解谜 / 轻量 Steam 主线 Devlog / Jam **作品集式**复盘 | 纯站长深水教程、学生羊毛、通用软件清单、主机圈社区流水账、隐私转载长文 |
| 与主线开发关系 | 写完不阻塞 `steam-game-01`；可复用已有截图/笔记/Jam 素材 | 需要新搭服务、长清单维护、跟进权益失效的内容 |
| 读者预期 | 「这个人在做时间机制叙事解谜游戏」 | 「这个人在教搭博客/薅学生云」 |
| DelayTrace | 允许作为 **Jam 履历一句/一链** | 禁止做成连载产品更新、路线图中心 |
| 处置 | 可进首页精选、新 `game-dev` Topic、导航强调、`pinned` 慎用 | 仍可搜索与归档；从首页 featured / 主导航 / Topic 主列表撤出；`section: deals` 维持隔离 |

### 2.2 内容类型 → 分类/标签映射

| 内容类型 | 建议 category | 建议 tags（择 2–4） | 可见性 | 说明 |
| --- | --- | --- | --- | --- |
| Godot / 时间机制技巧 | 游戏开发 | Godot, 教程, 时间机制 / 多窗口 / 叙事 | 主线留存 | 优先可迁移到主线的通用技巧 |
| Jam 复盘（含 DelayTrace 一句） | 游戏开发 | game-jam, 复盘, 独立游戏 | 主线留存 | 作品集叙事；不写「DelayTrace 下一步」 |
| 主线轻量 Devlog | 游戏开发 | 独立游戏, Devlog, 叙事解谜 | 主线留存 | 只写已完成里程碑；无剧透强依赖 |
| Steam / 发行流程笔记 | 游戏开发 | 创作者, 教程, Steam | 主线留存 | 已有注册文；后续补商店页/构建管线即可 |
| 创作者自省（轻） | 个人记录 | 创作者, 复盘 | 主线留存（少量） | 与游戏身份相关；避免每周鸡汤 |
| 站长教程（Astro/CF/自托管） | 建站与自托管 | 教程, 自托管, Cloudflare… | 降曝光 | 保留 SEO；撤出品牌主叙事 |
| 工具清单（通用） | 工具与资源 | 资源整合, … | 降曝光 | Godot 插件清单除外→主线 |
| Godot 插件/创作资源清单 | 游戏开发 或 工具与资源 | Godot, 资源整合, 开发工具 | 主线留存 | 已有「很有用的Godot插件」→保留高可见 |
| 社区记录（站长/主机圈） | 互联网与社区 | 中文社区, 叙事 | 降曝光 | Topic `webmaster` 内链即可 |
| 转载（隐私/流氓 App 等） | 互联网与社区 | 随笔, 隐私… | 降曝光 | 不删；不进精选 |
| 羊毛 / 学生权益 / AI 额度 | 工具与资源 或 AI 与工作流 | 学生资源… | 降曝光 | 强制 `section: deals` |
| 旅行 / 纯日记 | 旅行与生活 / 日记 | — | 降曝光 | 日记继续走 diary 边界 |

### 2.3 落地建议（代码未改，仅约定）

短期（本季不强制改 schema）：

1. 新建 Topic：`game-dev`（时间机制 / Godot / Jam / Steam 路径），逐步成为首页关联主入口。
2. `webmaster` Topic：**降为次要**（仍发布、仍可从归档进），不再当作品牌门面。
3. 首页 `home/*.json`：DelayTrace / TimeRewindLinker 保留为 **Jam 作品列表**，文案避免「当前主力产品」。
4. 可选后续字段（另 PR）：`visibility: keep | demote` 或 tag `主线` / `归档可见`；在精选组件过滤 `demote`。
